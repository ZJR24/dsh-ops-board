# 工作报文（ops-board）

一份台账 JSON，渲染成一份报纸体例的工作台页面，并且**内置 AI 对话**——点开某条问题直接问，不用自己复述内容。

换项目只改两个 JSON，代码不用动。

> **这套东西是个模板。** 脚本只存一份（在这里），每个项目里的看板只放数据。
> 「问 AI」交给 Harness 会话，模板里不存密钥、不选模型。

---

## 30 秒跑起来

**在 Harness 里：侧栏「项目看板」→ 点一块板。** 看台账、翻页、切主题、问 AI 都在那儿。

想单独看页面（不经过 Harness）也行：

```bash
cd D:\WorkSpace-Tools\ops-board

npm run build     # 渲染 + 自检
npm run serve     # http://127.0.0.1:8790
```

或者双击 `start.cmd` —— 它自己生成页面、起服务、开浏览器。那个黑窗口别关。

**单独打开时只能看，不能问**：模板里没有接入点，「发送」会提示去 Harness 里打开。
另外双击 `dist\index.html`（`file://`）也能看，但改完台账不会自动重渲染 —— 那是服务的活。

改完 `ledger.json` 刷新浏览器就是最新，不用重跑命令。

## 界面

照「赛博蛋报」那套报纸体例复刻，不是通用后台模板：

- 纸纹底 + 内框 + 双线报头，报头左右两个「耳朵」放两条车道的计数
- 居中导航，当前标签红色下划线
- 标题前四像素红竖条，卡片左边框按状态着色
- 顶部右上角三套配色：**夜晚**（默认，照深色编辑器取色）/ **护眼**（整页豆绿压对比）/ **纸面**（报纸米色）。选择记在本机

样式全在 `scripts/lib/css.mjs`，改视觉只改那一个文件。

### 侧栏能收起来

左边那栏是索引（各车道进度、优先看哪几条、快照），看正文时它占地方，所以能收。

收起按钮照搬原版（赛博蛋报 `docs/ops/index.html` 的 `#rail-toggle`）：**一条竖排的长按钮，贴在侧栏右边缘、在侧栏这一列里垂直居中**，写着「收起」，底部一个小箭头。收起后它**原地不动**，只是文字翻成「展开」、箭头转向，侧栏留 50px 窄条给它站着。

| 入口 | 位置 | 说明 |
|---|---|---|
| 竖排长按钮 | 侧栏右边缘、垂直居中 | 跟原版同一位置；收起后原地变「展开」，不用满屏找 |
| 快捷键 `[` | 任意位置 | 在输入框里打字时不会抢键 |

关键几点（改样式时别动）：

- 按钮是 `<aside class="rail">` 的**第一个子元素**，`position:absolute; top:50%; right:0; width:28px; min-height:104px`，`transform:translateY(-50%)` 才是真正的居中
- 收起态挂在 `.page.rail-collapsed` 上，`grid-template-columns:50px minmax(0,1fr)` —— **不是把侧栏整栏拿掉**，否则按钮跟着消失，就再也展不开了
- 收起时 `.rail` 那条 `min-height:calc(100vh - 160px)` 必须留着，否则侧栏一矮，按钮会窜到顶上

展开态和收起态下，按钮的 `left/top` 实测与原版**逐像素相同**（1300×900 窗口：展开 355,476 / 收起 105,456）。

窄屏（≤1000px）自动变单列，索引挪到正文**后面** —— 否则打开先看到一屏索引，正文要滚很久才见到。
这种布局下没有「收起」这回事，按钮会藏起来，索引始终可见（否则会把宽屏上收起的状态带过来，变成索引凭空消失）。

### 搜索（Ctrl+F）与设置

顶栏右侧两个按钮：**「搜索」** 和 **「设置」**。

#### 为什么不用浏览器自带的 Ctrl+F

整本台账是**一个 HTML 文件里的 6 个视图**，没打开的那些视图、AI 面板里的对话，全都在 DOM 里躺着。
浏览器自带查找会把这些看不见的字一起算进命中，上一个/下一个还会停在你根本看不到的地方 ——
它只能滚到文字，**没法按条目跳**。

所以这里自己写了一层：按 <kbd>Ctrl</kbd>+<kbd>F</kbd>（macOS 是 <kbd>⌘</kbd>+<kbd>F</kbd>）唤出，
或者点顶栏「搜索」。它**只搜条目**，命中按条目分组列出来。

| 操作 | 效果 |
|---|---|
| 输入关键词 | 边打边出结果，右上角写「N 条 · M 处命中」 |
| <kbd>↑</kbd> <kbd>↓</kbd> | 在结果之间挪，挪到哪条哪条高亮 |
| <kbd>Enter</kbd> | 打开当前选中的那条（不选就是第一条） |
| 点任意一行 | 切到那条所在的视图并滚过去，卡片闪一下 |
| <kbd>Esc</kbd> | 收起搜索层 |
| 点 `✕` | 同上 |

跳过去时**收起来的卡片会自动展开** —— 复用第 31 轮那条「跳到被收起的卡片要展开」的兜底。

**搜哪些字段**：编号、标题、正文四个块（具体表现 / 影响 / 解决办法 / 复核方式）、证据、领域。
`section` 和 `evidence` 在台账里是**已经排好版的字符串**（`【具体表现】…`、`- 提交：…`），
所以这里是拿字符串匹配、再从 `【…】` 和 `- 类型：` 反推出「命中在哪个字段」，
**不是去遍历数组**。改数据结构时要注意这一层。

搜索范围、要不要带证据命中，都在「设置」里，**改完立刻生效**（开着的搜索层会当场重画）。

#### 设置

点顶栏「设置」打开。**全是本机偏好，只写 localStorage，不动台账文件**，所以换台机器就是另一套。

| 项 | 可选项 | 存在哪 |
|---|---|---|
| 主题 | 夜晚 / 护眼 / 纸面 | `ops-board-theme` |
| 正文字号 | 小 15 / 标准 16 / 大 17.5 / 特大 19 | `ops-board-set` |
| 侧栏 | 展开 / 收起（跟 `[` 键、竖排按钮同一状态） | `ops-board-rail` |
| 打开哪一页 | 六页任选，默许「跟着上次停留的位置」 | `ops-board-set` |
| 搜索范围 | 全部字段 / 只搜标题与编号 / 标题 + 正文 | `ops-board-set` |
| 搜索选项 | 结果里带证据命中 / 用 Ctrl+F 唤出搜索 | `ops-board-set` |
| 本机偏好 | 恢复默认 / 清空本机偏好 | — |

几个刻意的设计：

- **字号走倍率，不是改 `body` 的 px。** 只写 `--fs-scale` 变量，正文和正文级段落跟着缩放，
  卡片上的编号、时间、按钮**字号保持不变** —— 否则一调大，密排的索引行就散了。
- **「打开哪一页」是次级兜底。** 有上次停留的落点就还用落点（那个更符合直觉）；
  只有第一次打开、还没有任何落点记录时，才用这里选的页。
- **关掉「Ctrl+F 唤出搜索」后，浏览器自带的查找会还回去** —— 不是拦掉就完事，
  `preventDefault` 只在开关打开时才调。顶栏「搜索」按钮照旧能用。
- **「清空本机偏好」要点两次。** 第一次点只是把按钮变成「再点一次确认」，5 秒不动自动放弃。
  清空会扫掉所有 `ops-board-` / `ops-mini-` / `ops-fold-` 前缀的键 —— 包含主题、侧栏、落点、
  AI 对话缓存和面板状态，**只保留台账本身**。
- **设置不占导航标签。** 它是浮窗，不进 `config.views`，所以导航顺序和 `verify-board` 的
  序号校验都不受影响。

### 浮窗对话窗口

点「问 AI」出来的面板**不是贴着右边缘的一条抽屉，而是一块能拖能拉的小窗**。

| 想干什么 | 怎么做 |
|---|---|
| 挪位置 | 拖标题栏（「台账助手」那一行） |
| 改大小 | 拉四条边或四个角，光标会跟着变成对应方向 |
| 钉在最上层 | 点标题栏「置顶」，按钮变红表示已钉住 |
| 改「回答区 / 输入区」的比例 | 拖中间那条分界；键盘用 <kbd>↑</kbd> <kbd>↓</kbd>（<kbd>Shift</kbd> 步长更大），<kbd>Enter</kbd> 或双击回到自适应 |
| 变回原来的贴边抽屉 | 点标题栏「停靠」（按钮文字会变成「浮窗」） |
| 关掉 | 点 <kbd>×</kbd> |

位置、大小、置顶、分界高度都记在本机（`ops-board-win:<看板 id>`），**刷新、关掉再开都还在**。

几个刻意的设计：

- **窗口永远整块留在视口里。** 往屏幕外拖会被夹回来，视口变小（比如把浏览器拉窄）时窗口自己缩。
  不这么做的话，一次误拖就能把窗拖到看不见的地方，用户只能去清 localStorage 才救得回来。
  这条和「宽屏/窄屏都不许出横向滚动条」是同一条约束的两面。
- **置顶不是「本来就在最上面」。** 默认层级 **180**，**低于**搜索浮层（190）和设置弹窗（210）——
  打开 Ctrl+F 时该盖住浮窗，否则浮窗正好挡住搜索结果。点「置顶」才升到 205：盖住搜索，
  但仍然让设置压在它上面（设置是模态确认框，被一个对话窗盖住会让人以为点不动）。
- **拉边的时候对面那条边钉住。** 拉左上角只改左上，右下角不动 —— 否则窗口会一边变窄一边往右下跑。
  宽高都有底线（320×300），拉到最小是「顶住」而不是翻转成负的。
- **回答区永远留得下一条内容。** 分界上拉到顶时回答区保底 96px，此时手柄变灰 ——
  再拉也没用了，不提示会以为坏了。
- **停靠形态是同一个元素换了套定位**（`data-mode="dock"`），不是另做一份面板。
  所以对话、已选会话、进行中的提问在两种形态之间切换都不会丢；停靠时拉伸手柄自动收起
  （拉不动就别装作能拉）。
- **状态用 `data-mode` / `data-pinned` 属性表达，不是加 class。** `verify-board` 对
  `class="…"` 里的动态类名有白名单，属性不在这套校验里，省得每加一个状态就改一次校验。

验收在 `npm run uitest:float`（51 项），全部用**真实鼠标事件**走一遍：

```bash
npm run uitest:float -- --board "<看板目录绝对路径>"
```

它盯的是几件「不做就会假通过」的事：拖标题栏拖得动、**按在标题栏按钮上拖不会把窗带走**、
八个抓手**都真的在最上层**（没被别的元素盖住）、拉左上角时右下角不动、往屏幕外拖会被夹回来、
**不置顶时搜索层盖得住浮窗**（否则「置顶」就是个摆设）、置顶后压过搜索但不压过设置、
拉分界时回答区让出高度而窗高不变、刷新后位置/大小/置顶/分界都还在、视口变小窗口自己缩、
存了个屏幕外的坐标也能救回来、「清空本机偏好」会把窗口位置一起扫掉。

配套还有一条**负向验收**（`npm run uitest:float-negative`）：把五个能力逐个拆掉
（去掉标题栏拖动 / 少一个抓手 / 去掉分界拖动 / 去掉置顶的层级规则 / 去掉存盘），
确认对应的断言**真的会变红**，再原样还原并确认回到全绿。
全绿的测试如果拆了功能还是全绿，那它测的就不是功能。

### 脱离看板的独立对话窗

上面那扇浮窗再能拖，**也拖不出看板页面本身** —— 看板跑在一个 iframe 里，
页面内的 `position:fixed` 只在这个 iframe 的矩形里生效。所以它盖不住侧边栏和顶栏，
也没法把窗口挪到看板外面去。

点标题栏的**「弹窗」**，出来的就是另一回事了：这扇窗由 DSH 插件画在**外壳层**
（挂在 `document.body` 上、`position:fixed`、层级压在最上面），所以它相对**整个应用窗口**定位 ——
可以盖住侧边栏、盖住顶栏、拖到任何地方。

| 想干什么 | 怎么做 |
|---|---|
| 弹成独立窗口 | 点对话面板标题栏的「弹窗」 |
| 挪位置 | 拖独立窗口的标题栏 |
| 改大小 | 拉八条边/角 |
| 钉在最上层 | 点独立窗口标题栏的「○」→「●」 |
| 收起 / 展开 | 点「—」（只留标题栏，不卸载内容） |
| 关掉 | 点独立窗口的「×」（**只关这扇窗，不动看板页面**） |

独立窗口里装的是**同一份看板页面，只是带 `?chat=1`**。那份页面加载时先给自己的
`<html>` 打上 `data-chat="1"`，然后 CSS 把报头、导航、正文、搜索、设置全部收起来，
只留对话框铺满整个矩形。这么做而不是另写一套对话 UI，是因为对话的全部逻辑
（作用域、历史、会话映射、分界、主题）都已经在那一份页面里了，复制一遍必然走味。

几个刻意的设计：

- **它是外壳层的一块 DOM，不是 slot。** 宿主 slot 的投影尺寸由它自己的容器决定，
  实测过「注册成功、`active:true`、但渲染出来不可见且不报错」。这里要的是相对整个视口
  定位的浮层，直挂 `document.body` 最稳。
- **单独的 React 根，不是 portal。** portal 要求有个 React 父组件常驻，而那个父组件
  （看板面板）恰恰是会被卸载的那个 —— 用户切到别的页、收起面板，对话窗就该还在。
- **`?chat=1` 里绝不跑页面级启动。** 搜索、设置、落点记忆、面板状态**统统不执行**，
  也**不往 localStorage 写面板/几何状态**：两个 iframe 共享同一套 `ops-board-*` 键，
  谁都能写就会互相覆盖。这条由 `CHAT_ONLY` 早退保证，并被验收里单独一节盯着。
- **拖动时会捕获指针，并让 iframe 忽略指针。** 窗口本体就是个 iframe，光标一压到它上面，
  `pointermove` 就会被那个文档吃掉，表现是「拖到一半卡住」。`setPointerCapture` 加
  `.is-moving .ob-chatwin-frame{pointer-events:none}` 两道保险都上。
- **几何也记在本机**（`ops-board-chatwin` / `ops-board-chatwin-pin`），键同样走 `ops-board-`
  前缀，所以「清空本机偏好」会一起扫掉。窗口永远整块留在视口里，视口变小会自己缩。

验收分三层：

```bash
npm run uitest:chatwin -- --board "<看板目录绝对路径>"   # 33 项，真实浏览器
npm run uitest:chatwin-wiring                           # 43 项，纯 Node，不需要浏览器
npm run shot:chatwin -- "<看板目录绝对路径>"              # 出两张预览图
```

`uitest:chatwin` 走真实浏览器，盯的是 `?chat=1` 那一半：骨架真的全没了、面板真的铺满
（宽度必须**正好等于视口**，少 15px 就是滚动条槽没关）、拉角/置顶/停靠按钮全部收起、
分界还能拉、**关窗不会把面板自己藏掉**、并且**没有往主看板的状态键里写过东西**。

`uitest:chatwin-wiring` 是外壳那一半：插件那半边只有重启 Harness 才会被加载，而重启会打断
会话。但接线错误（消息类型对不上、几何算法算错、关掉后开不回来）完全可以在 Node 里用假
React / 假 DOM 跑出来 —— 它验的是**逻辑对不对**，不是画出来好不好看。

它还会验一件容易漏的事：回答是**广播**给所有 iframe 的，两个窗口同时开着就会串台。
所以提问时把来源写进 `askId`（`ask-<c|p>-…`），收回答时**先认 `askId`、再认 `surface` 字段**。
测试里**故意装成旧版 Host**（把 `surface` 落回默认的 `page`），确认独立窗仍然只收自己那份 ——
这样即使 Host 那半边还没重启，窗口也不会收不到回答、或抢走整页的气泡。

`shot:chatwin` 补的正是「画出来好不好看」这一块，而它**不能替代真机验收**，只是把最能说明
问题的那一点拍下来：窗口是不是真的盖住了侧边栏和顶栏。做法是从插件源码里**抽出那段
`.ob-chatwin` CSS**（不是重写一份），套在一个假外壳（侧边栏 + 顶栏）上，里面嵌**真的**
`?chat=1` 页面，然后量 `win.left < side.right` / `win.top < top.bottom` 并截图。
CSS 是抽的、页面是真的，所以样式和内容都对得上；但外层那个「Harness 外壳」是假的 ——
**它只能证明「窗口有权盖住外壳」，不能证明「插件在真机上真的挂上去了」**。真机验收还得重启。

另外两条负向验收同样在：`uitest:chatwin-negative` 把「骨架藏起来 / 关滚动条槽 / 收起拉角 /
收起按钮 / 静音状态回写 / 静音几何回写 / 打 `data-chat` 标记」逐个拆掉，确认断言真的会红。

> ⚠️ 这一扇窗需要**改插件并重启 DSH** 才能用（只改模板不重启，按钮点了不会有反应）。
> 另外要说明白：这台机器上的 DSH 是 Electron 应用，但**插件拿不到任何原生窗口 API** ——
> 三条 `new BrowserWindow` 都在主进程里、且不对插件开放。所以「独立」的准确含义是
> **「脱离看板页面、覆盖整个应用窗口」**，不是「系统级独立窗口」。

### 跳转是怎么走的

页面里所有能点的地方都落到同一套规则上：

| 点什么 | 去哪 |
|---|---|
| 导航六个标签 | 换页并回顶部，标签高亮跟着走 |
| 页首状态表里的数字格 | 只留那一组（详情区其余分组收起），再点一次恢复；总览页没有表，这条不适用 |
| 车道页「待处理」表格里的编号（如 `BUG-011`） | 滚到同页那张卡片，**卡片闪一下红**告诉你落点 |
| 侧栏面板标题（「问题」「需求」「风险」） | 进对应车道页；鼠标移上去标题会下划线并出现 `→` |
| 阶段格子 / 阶段数字 | 滚到该阶段分节 |
| 浏览器后退 | 回到上一页，高亮同步 |

两个容易漏的地方，已经处理掉了：

1. **跨视图跳转要等两帧再量位置**。元素刚从 `display:none` 变显示，立刻量到的高度是 0，滚过去会歪。
2. **同一个链接连点两次也要有反应**。`hashchange` 第二次不触发，这里专门兜了一层，否则用户会以为"点了没反应"。

## 交互自检（带截图）

`npm run build` 只能查静态问题（重复 id、孤儿样式、死链）。**点击能不能用、收起来会不会错位，它查不出来。**

所以另有一个真浏览器跑的验收：

```bash
npm run serve        # 先起服务（另一个窗口）
npm run uitest       # 另开一个窗口跑
```

它用本机的 Edge（无头模式）真的去点按钮，逐项检查：首屏落位、侧栏收起/展开/记忆、六个导航标签、跨视图跳转有没有滚到、侧栏标题能不能进、后退、连点两次、三套主题、问 AI 面板、900px 窄屏不溢出，最后看控制台有没有报错。

截图落在 `.uitest/`（已排除 git），失败会指名哪一项不通过、退出码非 0。

它会用 `file://` 方式打开页面，点「问 AI」、点「发送」，然后检查面板有没有说人话：
有没有冒出 `NetworkError`，有没有讲清「要在 Harness 里打开」。

**搜索与设置另有一套验收**（要真的敲键盘、真的改字号，静态检查看不出来）：

```bash
npm run uitest:finder -- --board "<看板目录绝对路径>"
```

69 项。除了「点了会开」，它专门盯这几件容易做假的事：

- 正文里的词**确实能搜到**，且命中行标的**是正文块名**（`具体表现`），不是笼统的「正文」
- 把范围改成「只搜标题」后，正文词**真的搜不到**了；改回去**立刻又能搜到**（不用重启）
- 标题**不会**在结果里被念两遍（分组头已经带高亮了，不该再补一行「标题 …」）
- <kbd>Enter</kbd> 跳过去之后，**收起来的卡片真的展开了**、hash 对得上、所在视图变成激活
- 字号调大后 `body` 真的变大，而卡片上的**编号字号不变**
- 主题 / 字号 / 侧栏 / 默认页**重载之后还在**
- 「清空本机偏好」**第一次点不删东西**，第二次才删干净
- 关掉 Ctrl+F 开关后，`preventDefault` 返回 `false`（浏览器自带查找被还回去了）

`npm run shot:finder` 会拍四张截图（夜晚/纸面 × 搜索/设置）到工作目录，供人眼看配色。

## 面板说「要在 Harness 里打开」，是什么意思

这页有两种东西：**界面**（HTML，一个文件，双击就能看）和**后端**（`scripts/serve.mjs`，管自动重渲染和静态服务）。

| 你怎么打开这页 | 看台账 | 问 AI |
|---|---|---|
| Harness 里（侧栏「项目看板」） | ✅ | ✅ 交给 Harness 会话 |
| 双击 `start.cmd` | ✅ | ❌ 提示「要在 Harness 里打开」 |
| 双击 `dist/index.html`（`file://`） | ✅ | 同上 |

后端不影响问 AI —— 它只负责「改完台账自动重渲染」和把 `dist/` 发出去。
所以**看台账永远不需要后端**，也永远不需要先配什么。

## 台账怎么写

### 顶层

```jsonc
{
  "project":    { "name": "项目名", "subtitle": "一句话定位" },
  "updatedAt":  "2026-11-04T19:30:00+08:00",
  "headline":   "本轮一句话结论（页面最上面那句大字）",
  "deck":       "补充一句，讲清这轮的边界",
  "conclusion": "结论正文（页面上按双栏排）",
  "highlights": [ { "kind": "feature|fixed|watch|risk", "text": "写用户能感知到的结果，不写实现" } ],
  "metrics":    [ { "label": "指标名", "value": "当前值", "status": "ok|warn|danger", "note": "依据" } ],
  "snapshot":   { "branch": "", "commit": "", "onlinePackage": "", "deploy": "", "tests": "" },
  "items":      [ ... ],
  "history":    [ { "at": "2026-11-04T18:00:00+08:00", "kind": "found|fixed|deploy|ops|feature", "text": "做了什么，依据是什么" } ]
}
```

### 一条条目

```jsonc
{
  "id": "BUG-018",                  // 编号，前缀要跟车道一致
  "lane": "bug",                    // 属于哪条业务线
  "title": "一句话说清现象",
  "status": "fixed",                // 必须在车道定义的状态里
  "severity": "high",               // 可选；车道没配等级表就不写
  "area": "影响范围",
  "sections": [                     // 四段式，段数不限
    { "label": "具体表现", "text": "..." },
    { "label": "影响",     "text": "..." },
    { "label": "解决办法", "text": "..." },
    { "label": "复核方式", "text": "..." }
  ],
  "evidence": [                     // 这是整套东西最值钱的地方
    { "kind": "command", "text": "node scripts/verify-pages.cjs" },
    { "kind": "file",    "text": "pages/article/list.js 的 onLoad" },
    { "kind": "value",   "text": "实测首屏 1.2s（改动前 3.8s）" }
  ],
  "updatedAt": "2026-10-26T15:40:00+08:00"
}
```

`evidence.kind` 只有四种，别省略：`command`（能跑的命令）/ `file`（能打开的文件）/ `value`（实测值）/ `url`、`commit`。

**为什么要分？** 因为 AI 要据此判断哪些能去跑、哪些只能对照。混在一起它只能复述。

## 问 AI：只有一条路

面板里的「问 AI」**没有自己的接入点**。它把问题交给 Harness，由 Harness 开会话、选模型、执行。
模板里不含任何密钥、接入点、模型名、体检逻辑 —— 那些都在 Harness 那边，一份就够，不用每个项目副本各配一份。

**为什么不做自带的 AI 接入**：

- 密钥只能放服务端，于是每个看板副本都得有一份 `ai.config.json`，还得自己保证它不进 git；
- 模型名、命令行参数、登录状态每个 agent 都不一样，这套东西一改就得同步到所有副本；
- 而 Harness 本来就已经登录、已经选好模型了 —— 再让看板问一遍「你要用哪个 AI」是重复的。

所以现在是：**看板负责「记什么」，Harness 负责「谁来答」**。

### 面板里有什么

| 控件 | 干什么 |
|---|---|
| 上下文标签 | 显示这次问的是哪一条（`BUG-024 · 标题`）或整本台账 |
| 快捷动作 | 点一下只**填进输入框**，不自动发送；发不发由人决定 |
| 新会话 | 下一条发送新开一个 Harness 会话，旧会话保留在侧栏 |
| 发送 | 交给 Harness，在那边的会话里执行 |

### 作用域：单条 / 单车道 / 整页 / 整本台账

| 从哪进来 | 动作集 | 范围 | 动作写在哪 |
|---|---|---|---|
| 某条台账卡片的「问 AI」 | 现在什么情况 / 讨论 / 方案 / 解决 | 这一条 | **配置** `ask.itemQuick` |
| Skill 页某一行的「问 AI」 | 总结并更新这一个 / 只总结 / 查冲突 / 查缺什么 / 查该删的 | **只这一个 `SKILL.md`** | 代码 |
| Skill 页顶部入口 | 更新所有 Skill / 检查冲突 / 检查冗余 / 检查该补没补的 / 只报告 | 本页全部 skill | 代码 |
| 问题页「待处理问题」右侧「总结项目状态」 | 总结并更新台账 / 只总结 / 检查是否过期 / 更新台账 | 整本台账 | 代码 |
| 风险页「待处理风险」右侧「风险审核」 | 审核这些风险 / 哪条最该先处理 / 找出没记进来的风险 / 只报告 | 风险车道（未解除的那些） | 代码 |
| 需求页「计划中」右侧「和 AI 谈谈要加什么」 | 还缺什么功能 / 下一批做哪几个 / 把想法拆成条目 / 先看看现状 | 需求车道（全部条目） | 代码 |

**只有单条那套能在配置里改。** 另外几套写在 `scripts/lib/client.js` 里，故意不开放配置：
它们的 prompt 必须点名作用域（「只改这一个文件」「只审风险车道」「总结整本并写回台账」），
让项目配置去覆盖，很容易把作用域改坏 —— 比如把「只改这一个」换成一句泛泛的「更新一下」，
agent 就会顺手改动同目录的其它 skill。

三个「按车道聚合」的入口（风险审核 / 新增功能 / 整页 Skill）各用独立会话键，
不和整本台账串 —— 它们的 `ctx` 都是空的，若不加区分都会算成 `__global__`。

字段名带 `item` 就是为了让这件事在名字上就能看出来。旧版本叫 `quick`、看着像「所有快捷动作都归它管」，
实际只作用于单条，已经改名；`globalQuick` / `skillQuick` 两个从来没人读的字段已经删掉。
`verify-board.mjs` 会拦住这些旧字段名，防止有人再写回去。

单条 skill 的 prompt 里写死了这句，防止 agent 顺手改别的：

```
范围：只有这一个 Skill ——「xxx」
作用域限制：只读、只改这一个 SKILL.md；不要读改同目录或 skill 根里的其它 skill。
```

### 点「发送」到底发出去什么

面板不是把整本台账灌给 agent，而是**按你点的位置**拼一段：

| 作用域 | 发出去的内容 |
|---|---|
| 某条台账 | 看板名 / 项目目录 / 「只有这一条」/ 编号 / 标题 / 车道 / 状态 / 严重度 / 区域 / 最近更新 / **四段记录全文** / **证据全文** |
| 单个 skill | 看板名 / 项目目录 / 「只有这一个 Skill」/ 作用域限制 / 文件路径 / 标题 / 版本 / 使用次数 / 说明 |
| 整页 skill | 看板名 / 项目目录 / 「本页全部 Skill」/ 清单（标注会话里用过的、项目产出的、为它写的） |
| 整本台账 | 看板名 / 项目目录 / 总数与未收口数 / 提醒去读 `ledger.json` |

四段和证据是**全文**带上的，所以条目内容长的时候这段也会长 —— 内容最全的那条 `FEAT-014`
（四段 2086 字 + 证据 1559 字）发出去是 4308 字，属于正常。

末尾再接一段「这次要你做的事」，以及 `ask.systemPrompt` 里的**【回答规则】**（那 6 条：
不许编造数字、没有实测证据别建议改成已修复、不要动 `ledger.json` 和 `board.config.json`……）。
规则是三个作用域共用的，所以放在问题前面 —— 先讲怎么答，再讲答什么。

`ask.systemPrompt` 模板里的【台账现状】和【当前关注】两段**不会**发出去：上面按作用域给的
内容更准，重复一遍只会更啰嗦，`{{focus}}` 还会留下一个空标题。只取【回答规则】。

> 早先这里有个 bug：单条和整本共用一个分支，而那个分支只写了 skill 的话术。
> 点某条的「问 AI」发出去的是「范围：本页全部 Skill（共 0 个）」加一句「skill 文件是 SKILL.md」，
> 那条台账的编号、标题、四段、证据一个字都没带上。现在三个作用域各拼各的，
> `uitest.mjs` 会真发一次并检查发出去的内容里有没有这一条。

### 裸页打开会怎样

直接双击 `dist/index.html`（没经过 Harness 注入）时，页面照样能看能翻，但点「发送」会提示：

> 这块板要在 Harness 里打开才能问 AI（侧栏「项目看板」）。

不会抛 `NetworkError`，也不会静默失败。

### 不要问 AI 的看板：`ask.enabled`

想拿这块板纯当静态台账看，把 `ask` 整个关掉：

```json
{
  "ask": { "enabled": false }
}
```

关掉之后**面板和所有入口按钮都不渲染** —— 条目卡片的「问 AI」、Skill 页每行的「问 AI」、
「问整页 Skill」、「总结项目状态」（问题页）、「风险审核」（风险页）、
「和 AI 谈谈要加什么」（需求页「计划中」），一个都不留。留一个点了没反应的按钮比没有按钮更糟。

`ask.title` 是面板标题，默认「台账助手」。

> 这里以前有个坑：`aiPanel()` 关了面板，但按钮是别处渲染的，照样生成；
> 而 `client.js` 里 `$("ai-send").addEventListener(...)` 碰到 `null` 直接抛
> `TypeError`，把后面 30 多行（全局快捷键、页面入口）一起带走。
> 现在两头都改了：渲染层按开关不生成按钮，client 层在绑定前先判 `panel` 在不在。
> `verify-board.mjs` 和 `uitest.mjs` 都按开关分两种状态验，关掉的看板跑自检不会误报。

### 只想把上下文复制到别处

不开浏览器也能导出「台账 + 问题位」，粘到任何 AI 里都行：

```bash
node scripts/ask.mjs                # 整本台账
node scripts/ask.mjs OPS-030        # 只围绕某一条（编号用 --list 查，各项目自己定）
node scripts/ask.mjs --list         # 看有哪些编号
node scripts/ask.mjs OPS-030 | clip # 直接进剪贴板
```

## 换项目 / 加一条业务线

只改 `board.config.json`，代码不动。

### 例：加一条「客户反馈」线

```jsonc
{
  "key": "feedback",
  "label": "反馈",
  "prefix": "FB",
  "countNoun": "反馈",
  "openNoun": "待回应",
  "rankBySeverity": false,
  "stages": [
    { "key": "new",      "label": "待回应", "statuses": ["waiting"],  "tone": "danger", "open": true },
    { "key": "handling", "label": "处理中", "statuses": ["handling"], "tone": "info",   "open": true },
    { "key": "done",     "label": "已回应", "statuses": ["replied"],  "tone": "ok",     "open": false }
  ],
  "statusLabels": { "waiting": "待回应", "handling": "处理中", "replied": "已回应" }
}
```

再在 `views` 里加一条 `{ "key": "lane:feedback", "label": "反馈", "kind": "lane", "lane": "feedback" }`，就多出一个标签页。

- `open: true` 的阶段计入红色大号数字（"未收口"那个数）
- `rankBySeverity: true` 才按严重度排序，非技术车道设 `false`
- 不写 `severity` 等级表，页面上就没有严重度列和实心色块——不会露馅

### 配置里哪些字段真的有用

`board.config.json` 的字段全部会被读取，没有摆设。几条容易搞错的：

**四段标题不在这里配。** 它们是 `ledger.json` 里每条自己的 `sections[].label`：

```jsonc
// ledger.json
"items": [
  { "id": "BUG-018",
    "sections": [
      { "label": "具体表现", "text": "..." },
      { "label": "影响",     "text": "..." }
    ] }
]
```

所以想让四段叫「现象 / 原因 / 处理 / 验证」，改每条条目的 `label`（或改 `ledger.json` 里的初始数据），
不是改配置。以前配置里有个 `sections.defaultLabels` 看着像干这个的，其实从没被读过，已经删掉；
`verify-board.mjs` 会拦住它，防止有人再写回去。

**`schemaVersion` 现在是会校验的。** `board.config.json` 和 `ledger.json` 都带这个字段，
`render.mjs` 认 2：

| 情况 | 结果 |
|---|---|
| 等于 2 | 正常渲染 |
| 没有这个字段 | 提醒一句，按 2 处理，继续渲染 |
| 不等于 2 | **报错停下**，说明只认哪个版本 |

以前这个字段只写不读，改数据格式时旧看板会静默渲染出错的东西；现在至少会拦住。

**`labels.*` 都能配。** 侧栏与各视图的标题、按钮文案都在 `labels` 下：`overviewHint`、
`historyTitle`、`metricsTitle`、`snapshotTitle`、`copyButton`、`tableHeaders`，以及 Skill 统计页的
`skillsTitle`（默认「Agent 用过的与产出的」）。以前 `skillsTitle` 在代码里读了但配置里没有，
页面永远用默认值、改不了——现在补上了，和其它 `labels.*` 一样可配。

**`metricStatuses` 是「配置 ↔ 渲染 ↔ 样式」的契约。** 侧栏「概览指标」每一条有自己的
`status`，渲染时拼成 `.metric-<status>` 去取配色：

```jsonc
// board.config.json
"metricStatuses": ["ok", "warn", "danger", "muted"]
// ledger.json
"metrics": [{ "label": "未收口", "value": "5", "status": "warn", "note": "..." }]
```

台账里写了表外的值（比如 `purple`），页面不会报错，只是那条指标**悄悄没有配色**——
以前正是靠「class 在 CSS 里没有规则」这条间接撞出来的，报错信息看不懂。现在两处都拦：
`render.mjs` 把表外值回落到 `muted` 并照常出页，`verify-board.mjs` 直接点名是哪条指标写错了，
同时检查「配置声明了几档，CSS 就必须有几条规则」。要加一档配色，三处一起改：
`metricStatuses` 加值、`scripts/lib/css.mjs` 加 `.metric-<值>` 规则、需要时 `parts.mjs` 里给默认值。

**`priority.rule` 已经删了。** 它写的是 `"open-first"`，但排序真正由每条车道自己的
`rankBySeverity` + `severity` 等级决定（`priorityItems()` 对全部未收口条目按严重度排）。
`rule` 字段从没被读过——改了没效果还不报错。想调排序，改 `lane.rankBySeverity` 和 `lane.severity.levels`
的顺序，不是改 `priority.rule`。`verify-board.mjs` 会拦住它，防止有人再写回去。

**`priority.label`（侧栏标题）和 `priority.limit`（显示条数）是活的**，改它们有效。

```
│  ├─ serve.mjs             ← 本地服务：预览 + 自动重渲染
│  ├─ ask.mjs               ← 命令行导出上下文
│  ├─ collect-skills.mjs    ← 统计这个项目相关的 skill
│  ├─ export-board.mjs      ← 导出一份干净、自包含的看板成果
│  ├─ gen-ledger.mjs        ← 把一批候选条目规范化成合法台账（分 lane/编 id）
│  ├─ uitest.mjs            ← 真浏览器点一遍（要服务起着）
│  ├─ offline-test.mjs      ← 服务关着时会说什么
│  └─ lib/
│     ├─ css.mjs            ← 全部样式
│     ├─ parts.mjs          ← 数据 → HTML 片段
│     ├─ context.mjs        ← 上下文（页面和命令行共用）
│     └─ client.js          ← 页面交互（路由、主题、AI 面板）
└─ dist/index.html          ← 生成物，不要手改
```

**唯一真源是 `ledger.json`。** HTML 是派生物，改了下一次渲染就没了。

**这里没有 `ai.config.json`**：问 AI 交给 Harness，模板不存密钥、不选模型。

## 脚本只有一份

模板里的 `scripts/*.mjs` 是真身。项目里的看板**只放数据**，`scripts/` 下的每个文件都是
几行转发入口：找到模板 → 把参数原样转给同名脚本 → 退出码透传。

所以升级渲染或服务逻辑，改模板一处，所有看板立刻生效，不用逐个重拷。

### 规则：模板里有什么，看板里就有什么

入口名单**不是手写的**，而是扫模板的 `scripts/` 目录得出来的（`index.js` 的 `entryScriptNames`）。
手写名单踩过坑：`package.json` 声明了 `ask` 和 `uitest:offline`，名单里却没有对应的入口，
于是在看板里跑就是：

```
Error: Cannot find module '...\scripts\ask.mjs'
```

自检现在盯这条不变量，两个方向都查：

- `package.json` 声明的每个 script，必须有对应入口文件
- 模板里每个 `scripts/*.mjs`（`entry.mjs` 除外），必须有对应入口文件

老看板不用手动修：插件启动看板时会 `ensureEntryScripts` 补齐缺的几个，只补不覆盖。

### 转发脚本也认 `--board`

`ask.mjs` 和别的脚本一样，按 `--board` / `OPS_BOARD_DIR` 定位看板目录。
少了这一段，从看板里跑 `node scripts/ask.mjs` 读到的是**模板自己的台账** ——
条目数看着不对，却不会报错，最难发现。

### 导出一份干净成果给别人

平时用的看板是「瘦客户端」：目录里只有数据 + `scripts/` 转发入口，真正的脚本在模板目录，
靠 `project.json.templateDir` 或转发入口里的本机路径指过去。**这不能原样拷给别人**——
收件人机器上没有那个模板路径，脚本会全找错。

`export-board.mjs` 导出一份自包含、可独立跑、可上 GitHub / Gitee 的项目：

```bash
node scripts/export-board.mjs --project 项目名 [--out D:\Output] [--from <看板目录>]
```

它做的事：

- 复制数据（`board.config.json`）+ **空台账**（清空条目/记录），放在 `<out>/<项目名>`
- 复制**真脚本**（丢掉 `entry.mjs` 转发层和转发用的本机路径）
- 生成干净的 `package.json`（含 `build` / `serve` / `verify`）+ `README` + `.gitignore`
- 用空台账渲染一份 `dist/index.html`（收件人双击/静态托管即可看，无需 Harness）

默认从**模板根**导出最干净的骨架（空台账）；`--from <看板目录>` 指定某个业务看板时带它自己的数据。

关键不变量（都有验证）：导出物里**没有** `project.json`、`entry.mjs`、`uitest.mjs`、
`export-board.mjs` 自身，也不含任何写死的本机路径（`collect-skills.mjs` 里用的是 `homedir()`，
收件人会落到他自己的家目录）。导出后在里面直接 `npm run build` + `npm run serve` 就能跑。

> 空看板是合法状态：`verify-board.mjs` 对 0 条目的骨架放行（结构、schema、配置仍严格检查），
> 但非空看板的字段守护一分不减——做了变异测试确认。

### 用 gen-ledger.mjs 登记一批条目

不猜语义，只做规范化：读 `board.config.json` 拿合法车道/状态/严重度，把一批候选条目
（标题 + 可选四段式）变成 render/verify 认得的合法台账，按车道续号 `BUG-021` / `FEAT-012` / `RISK-005`。

```bash
node scripts/gen-ledger.mjs --items-file 候选条目.json [--board <看板目录>] [--dry-run]
```

- 候选文件是 JSON 数组：每条至少要 `title`；`lane`/`status`/`severity`/`sections`/`evidence` 可省
- `lane` 缺省按关键字猜（bug/报错/白屏…→ bug；新增/支持…→ feature；风险/额度/接近…→ risk）
- `status` 缺省取车道第一阶段；`severity` bug/risk 缺省 `medium`，feature 不填
- id 缺省自动编，续号从该看板已有条目算（**只看目标的 ledger，绝不写模板**）
- 先 `--dry-run` 看打算加什么，确认后再真写

**写之前会预检整份 ledger，不通过就一条都不写。** 这条是有意设计的：一旦落盘，脏数据就得手工回滚。
预检拦三类：

| 拦什么 | 为什么在写之前拦 |
|---|---|
| 显式 `id` 撞号 / 前缀不对 | 撞号 render 报 error、前缀错 render 只给 warning（静默放过），两种都得事后才发现 |
| 整份 ledger 的 `metrics[].status` 不在 `metricStatuses` | 同上，属于「页面不报错但配色丢了」 |
| 候选里的 `sections` / `evidence` 元素形状不对 | 只判「是不是数组」不够，传一堆字符串进来卡片会渲染成空壳 |

`sections` / `evidence` 的元素**必须带 `text`**，`sections` 带 `label`、`evidence` 带 `kind`；
纯字符串会被补上默认键（`label` 默认「具体表现」、`kind` 默认「记录」），缺 `text` 的对象会被跳过并报错。

## 为什么要自检

页面是脚本生成的，**人眼看不出的错**只能靠机器拦：

- 同一个条目 id 渲染两次 → hash 跳转会跳错位置
- `href="#xxx"` 没有落点 → 点了没反应
- 用了 class 但没有对应样式 → 元素裸奔
- 标签没闭合 → 布局错乱但控制台不报错
- 内联 JSON 解析失败 → AI 面板整个失效

`node scripts/verify-board.mjs` 一条命令全查完，退出码非 0 就是有问题。

除了「文件里长什么样」，它还盯几个**界面看不出、但用户一定会撞上**的约定：
侧栏收起的实现方式、跳转要等两帧再量、同一个链接连点两次也要有反应、
单条 skill 的作用域不能串到别的文件、裸页打开时不能甩 `NetworkError`。
这些删掉任何一处页面都不会崩，只会悄悄退回旧毛病 —— 所以专门写断言盯着，并且用变异测试证明断言真的会红。

**规矩：渲染完必须跑一次自检。** 不跑等于没做完。

### 一条命令跑完全部验证：`npm run gate`

改完东西不知道该跑哪几个测试？不用记。

```powershell
npm run gate          # 渲染双板 → verify-board → 25 套测试，逐项报耗时，任一失败 exit 1
npm test              # = gate --fast，跳掉 11 项慢的、实跑 14 项（约 188s，改完随手跑这个）
node scripts/gate.mjs --list            # 看登记了哪些套件
node scripts/gate.mjs --only workbench  # 只跑名字含 workbench 的
```

在此之前，20 个测试脚本没有注册表，「改了一处，跑了三个测试就以为没坏」。
现在「该跑哪些」写在 `scripts/gate.mjs` 的 `SUITES` 数组里，不靠记忆。

> 它上线第一天就抓出 3 个一直藏着的真 bug（两个测试缺参数导致假失败、一个超大提交的
> diff 会静默变空、一个调试端口竞态）。**门禁的价值不在它绿，而在它红的时候说的是真的。**

## 换机器怎么迁

看板的数据全在文件里，没有数据库、没有服务端状态 —— 拷目录就能走。但**有三处记的是旧机器的绝对路径**，
拷过去不改就会以各种看不懂的方式失败。逐个说。

### 迁什么

一个看板目录 = `ledger.json` + `board.config.json` + `project.json` + `scripts/`（7 个转发器）。
整个目录拷走即可；`dist/` 是生成物，`skills.json` 是缓存，都可以不带（会自动重建）。

```powershell
# 旧机器
Copy-Item <旧看板目录> -Destination <U盘或共享目录> -Recurse
# 新机器
Copy-Item <U盘里的看板目录> -Destination <新看板目录> -Recurse
```

### 三处要改的路径

| 文件 | 字段 | 记的是什么 | 不改会怎样 |
|---|---|---|---|
| `<看板>/project.json` | `templateDir` | 模板目录的绝对路径 | 转发器找不到模板，`render`/`serve` 直接失败 |
| `~/.dsh/ops-board/boards.json` | `boards[].dir` | 每个看板目录的绝对路径 | Harness 侧栏里点开会话，指向一个不存在的地方 |
| `<看板>/project.json` | `projectDir` | 业务项目目录的绝对路径 | 「问 AI」会把旧机器上的项目路径发给 agent，agent 找不到目录 |

改 `project.json` 很简单，两个字段都是路径：

```jsonc
// <看板>/project.json
{
  "projectDir": "<新机器上业务项目的路径>",   // 可以留空，留空就不带项目上下文
  "templateDir": "<新机器上模板目录的路径>"     // 建议留空，见下
}
```

**`templateDir` 建议直接留空。** 转发器按这个顺序找模板：

1. `project.json` 的 `templateDir`
2. 环境变量 `OPS_TEMPLATE_DIR`
3. **看板目录旁边的兄弟目录**（自动扫 `../` 和 `../../` 下各个子目录，认出「有 `scripts/lib/` 的那个」）

所以只要把模板目录和看板目录放在同一个父目录下，`templateDir` 留空就能自动找到：

```
<某个目录>/
├─ ops-board/          ← 模板（有 scripts/lib/）
└─ my-board/           ← 看板（有 project.json）
```

这一档是后加的：早先兜底写死了一个绝对路径，换机器后会指向一个不存在的地方，而报错只说
「找不到模板脚本」，看不出是兜底路径过期。现在改成扫兄弟目录，扫不到才报错，且报错会说清试过哪几处。

### 注册表：让 Harness 认识新位置的看板

`~/.dsh/ops-board/boards.json` 是 Harness 侧的登记表，看板目录搬了就得改。最省事的办法是
**让它自己重新登记**：删掉这一项，然后在 Harness 侧栏里重新添加。手改也行：

```jsonc
// ~/.dsh/ops-board/boards.json
{
  "version": 1,
  "last": "<上次用的看板 id>",
  "lastCreateDir": "",
  "boards": [
    { "id": "<看板 id>", "label": "<显示名>", "dir": "<新看板目录绝对路径>", "projectDir": "" }
  ]
}
```

### 转发器要跟着模板一起更新

`<看板>/scripts/` 下那 7 个文件**只是转发器**（真脚本在模板里）。它们是创建看板时**复制**进去的，
所以模板改了，老看板的副本不会自动跟着变 —— 这是迁移时最隐蔽的一个坑：
新模板已经修好了，老看板还跑着旧副本。

把模板的 `scripts/entry.mjs` 覆盖到每个看板的那 7 个文件名上即可（它们内容完全一样，只是文件名不同）：

```powershell
$src = '<模板目录>\scripts\entry.mjs'
foreach ($f in 'ask.mjs','collect-skills.mjs','offline-test.mjs','render.mjs','serve.mjs','uitest.mjs','verify-board.mjs') {
  Copy-Item $src -Destination "<看板目录>\scripts\$f" -Force
}
```

### 迁完检查

```powershell
cd <新看板目录>
node scripts/render.mjs          # 能出页面就说明模板找到了
node scripts/verify-board.mjs    # 退出码 0 才算迁完
```

两条都过，说明路径、数据、样式都对得上。`render` 报「找不到模板目录」就去查 `templateDir` 和
兄弟目录结构；`verify` 报错多半是数据本身的问题，跟迁移无关。

## 从旧项目迁过来

旧的「赛博蛋报」用 `issues` / `features` 两个数组 + 六状态 + 四份 HTML：

1. `issues` 每条加 `"lane": "bug"`，`features` 每条加 `"lane": "feature"`，合成一个 `items` 数组
2. `verification` 字段并进 `sections`（作为"复核方式"那段）
3. `evidence` 是纯字符串数组的，按内容分 kind：以 `node `/`npm `/`git ` 开头 → `command`；带 `.js`/`.mjs`/`.json`/`路径:行号` → `file`；其余 → `value`
4. `manifestation` / `impact` / `solution` 三段直接对应 `sections` 前三段
5. 顶层 `history` 保留，`kind` 已经对得上

旧渲染器 `scripts/render-report.mjs` 已拷进旧仓库（原来装在 Qoder 的 skill 目录，换机器就没了）。

## 已知道的边界

- **问 AI 只能在 Harness 里用**。双击 HTML 或跑 `start.cmd` 都只能看台账，点「发送」会提示去 Harness 打开 —— 因为模板里没有接入点，也没有能替它执行的东西。
- **这条会话记在 Harness 那边**。看板不维护对话历史，所以「新会话」只是让下一条不复用旧的；旧会话在 Harness 侧栏里找。
- **agent 在哪个目录里干活由 Harness 决定**。看板把项目目录一起发过去，但最终在哪儿执行是 Harness 的事。
- **一个人用没问题，多人同时改 `ledger.json` 会打架**。没有锁、没有合并。
- **`lane.key` 里不要带连字符**。hash 路由按 `stage-<lane>-<stage>` 切分。
- **不支持富文本**。文本按纯文本转义，写 `**加粗**` 会原样显示。刻意如此：台账要能被机器读，就别混排版标记。
- **AI 不会改台账**。它可以按「解决一下」去改你项目里的文件、跑命令，但 `ledger.json` 和 `board.config.json` 被系统提示禁掉了 —— 台账之所以可信，就因为不肯乱写「已修复」。要改状态得你自己动手。
